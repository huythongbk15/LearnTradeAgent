# Recording the scope approval — the exact steps

The scope change in prereg §13.3 (the frozen loader reads and decodes all 6795
rows of the pre-holdout file; the evaluation stays confined to [0, 5600)) is
recorded **inside the payload**, so it is part of identity B. Recording it is a
payload edit, therefore it **produces a new B**, and the run must be bound to
the B that carries the approval.

This is the operator's action. The steps below are mechanical and are checked by
`verify_approval_binding.py`; they do not require re-running the test suites.

## Precondition

An **independent review** by a reviewer other than the author must have issued
a verdict on the exact A/B/C under review. The author's own check round is a
self-verification and does not satisfy this.

## Step 1 — edit the payload

`data/bnb_di_adx_stateedge_prereg_20261020_01/preregistration_payload.json`, in
`data.scope_change_request`. **Exactly four fields**, and `approval_state` is the
**single authoritative state** — there is no second status field, so following
this procedure cannot be rejected by a field the procedure never sets:

```json
"approval_state": "APPROVED",
"approved_scope": "<must equal expected_approved_scope>",
"approved_by": "<role or identifier of the approver>",
"approved_at": "<ISO-8601 timestamp>"
```

`expected_approved_scope` is already in the payload:

```
read+decode 6795 rows of the pre-holdout file; evaluate only [0,5600);
0 reserved-holdout bars (last bar 2026-02-06T08:00:00Z, holdout opens 2026-02-06T16:00:00Z)
```

The binding gate checks exactly these four plus the identity, input hash,
params, windows, costs and budget. Nothing else in the payload may change; the
verifier enforces that.

## Step 2 — recompute identity B

```bash
.venv/bin/python -c "import hashlib,json,pathlib; p=pathlib.Path('data/bnb_di_adx_stateedge_prereg_20261020_01/preregistration_payload.json'); d=json.loads(p.read_text()); c=json.dumps(d,sort_keys=True,separators=(',',':'),ensure_ascii=False); print('NEW B =', hashlib.sha256(c.encode()).hexdigest())"
```

## Step 3 — refresh the three manifests

Set `identity_B_preregistration_fingerprint` to the new B and re-list the files in
`data/bnb_di_adx_stateedge_20261020_01/manifest.json`,
`data/bnb_di_adx_stateedge_prereg_20261020_01/manifest.json` and
`data/bnb_native_review_20261020_01/manifest.json`. The review round's own
outputs are excluded from the sealed lists. Note: the only `review_verdict.json`
that existed was a **stale rev10** file that predates the sealing — it has been
**archived** under `revisions/rev10/`, and it was never a post-sealing output.
`review_round_execution.json` is regenerated by the check round and is therefore
written after sealing.

**Before Step 1**: copy the current payload over `pre_approval_payload.json` in
the preregistration packet, so the verifier can show exactly which four fields
the approval changed. The verifier refuses a payload that differs from that
snapshot in any field outside the approval set, and it now compares the
assertion files against the **sealed** hashes in
`../bnb_di_adx_stateedge_20261020_01/evidence/assertion_files.json` and fails
loudly when a file is unrecorded (identity A does not cover `tests/`).

## Step 4 — verify the binding

```bash
.venv/bin/python data/bnb_di_adx_stateedge_20261020_01/verify_approval_binding.py
```

It must report `BINDING COHERENT` and `the scope change is APPROVED`, and it
checks that: only the approval fields changed; **identity A is unchanged** (no
code moved); **every assertion file is byte-identical** to the sealed manifest —
which is why the suites need **not** be re-run; the manifests' `identity_B`
matches the recomputed B; the affected manifest entries re-hash; and the
pre-approval B is not silently reused.

Exit codes: `0` coherent and approved · `2` not coherent, run blocked ·
`3` coherent but still pending, run not authorised.

## Step 5 — the run itself still needs its own approval

A preregistration, and an approved scope, are **not** a run authorisation. The
operator must still approve the scope and budget of one run before it starts.
The registered command is prereg §8.3: 15 inner cells (5 folds × 3 cost
scenarios), 300 s per cell, 5400 s total, 1 worker, `--max-retries 0`,
`--validation-only --no-real-sensitivity` (no outer OOS, no sensitivity, no
live), into a **new** packet directory.

## If anything else in the payload changes later

Any payload edit **after** the approval produces a new B and **invalidates the
approval** — a fresh approval is required before the run. The same applies to
any change to `src/` or `scripts/`: that moves identity A, so the approval must
be re-issued against the new revision.
